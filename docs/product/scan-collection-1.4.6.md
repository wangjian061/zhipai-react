# 知拍 1.4.6 扫码采集产品契约

更新：2026-10-23。五项整改均已按用户确认的结构图本地实施，待用户验收；提交与推送状态以 Git 记录为准，尚未发布站点。适用于首页、专项专区及项目身份认证内的扫码。视觉沿用知拍现有规范，由 Impeccable 按 Operate 模式把关。规范优先级：本契约与本轮确认覆盖旧的“读取成功后再验证”流程；专项其他业务保持。

配套：[已确认结构与实施记录](../reviews/scan-collection-20261023/review.md)、[设计规范](../../DESIGN.md#扫码采集2026-10-23)、[三端交付](../../HANDOFF.md#扫码采集交付契约2026-10-23)。普通项目列表进入详情仍不自动认证，只有本轮确认的扫码交接会自动打开认证。

## 一、用户任务与五项整改

用户需要用二维码找到正确的采集项目，按该项目规则完成本人的身份认证；不需要理解二维码协议或重复确认“读取成功”。

| 整改项 | 当前实现与边界 |
| --- | --- |
| 业务去向 | 两类码直接交接项目及认证阶段；消费扫码路由，不留读取成功中转；取消回来源，保留原项目输入及筛选 |
| 获取码帮助 | 一个上滑抽屉包含两类目录及本地正文，替换缺失的iframe；不叠加抽屉，不依赖另一张说明网页 |
| 读取与身份核验 | 区分解码、机构／项目关联、个人信息核对和匹配；不把字符串非空或机构码当作本人认证通过；保留原登录及付款规则 |
| 权限与恢复 | 相机、相册、文件选择、图片识别、项目解析分开；拒绝后不反复申请，关闭帮助恢复此前模式；限15 MB并分原因恢复 |
| 视觉统一 | 白色圆底返回、17px居中标题、取景优先、公共抽屉与固定操作区；无大幅说明插画，入口与状态克制清晰 |

## 二、页面结构与两类去向

扫码主页面：导航 → 支持范围 → 取景区 → 短提示 →「从相册识别」／可用手电筒 →「如何获取采集码」。相机未就绪时提供明确状态与手动开启／重试；手电筒仅在相机就绪且设备支持时显示。相机逐帧读取不占用相册按钮的“识别中”状态。

| 来源／读取类型 | 下一页 | 自动打开的阶段 | 不能发生的事 |
| --- | --- | --- | --- |
| 首页或专区／机构、院校码 | 对应采集项目首页 | 项目配置的首个认证入口；毕业生为上传或扫描本人学信网码；身份证、工号等沿用项目配置 | 不再等一次“开始采集”；机构码不置`qrRead=true`，不绕过本人认证 |
| 首页或专区／本人学信网码 | 按院校代码关联机构、再关联唯一项目的首页 | 现有“确认身份信息”第二步（`qrCheck`），回显确实取得的字段 | 不重复上传，不让用户选项目，不虚构姓名／学号，不展示读取成功中转 |
| 原项目认证内／本人学信网码 | 原项目首页 | 同一项目的第二步信息核对 | 必须校验归属，不静默切换项目；其他机构码不能替代本人码 |
| 关闭／未开始／入口暂停的项目 | 失败说明中可“查看项目” | 不启动认证；保留原查看详情及已有记录能力 | 不自动创建任务或付款，不借扫码绕过项目开放规则 |

扫码中取消：返回来源。原项目进入时保留项目、认证方式及已填字段；成功交接后扫码路由被替换，项目返回仍遵循原列表／栏目和筛选。首页／专区扫码进入的项目返回扫描前来源。认证抽屉顶部关闭先回项目，随后项目返回退出；帮助正文返回先回目录。浏览器返回在扫码抽屉打开时先关闭或回帮助目录，不造成相机与项目循环。

二维码解码成功 ≠ 项目关联成功 ≠ 本人身份认证成功。必须继续核对并“确认并匹配”后，才按原逻辑查找／创建任务，付款仍位于拍摄前，同一任务只支付一次。

## 三、帮助正文

### 如何获取机构／院校二维码

二维码由组织本次采集的机构或院校提供。查看采集通知或负责人／老师发送的二维码；保存在手机中的图片可从相册识别，现场二维码可直接扫描。未收到时联系本次采集负责人，不提供虚构的联系人按钮或自行生成机构码功能。

### 如何获取学信网图像采集码

1. 用本人账号登录学信网，进入学信档案。
2. 查看本人学籍；存在多条时，选本次采集对应的学籍。
3. 打开该学籍的图像采集码，保存清晰完整的原图。
4. 返回知拍，从相册识别，并核对本人采集信息。

帮助提供[学信档案官方外部入口](https://my.chsi.com.cn/archive/index.jsp)，知拍不收集学信网账号密码。外部页面以平台当前界面为准；本地帮助正文直接随原型交付，没有异步iframe加载环节，因此不增加空壳加载态或假重试。

资料依据：[暨南大学发布的获取方法](https://jwc.jnu.edu.cn/_upload/article/files/3f/1c/d0c0bbf24aa09b7c12d57f38445d/fb2f13f7-232e-431f-98f9-f9ee827f6d7a.pdf)支持“本人学籍→对应采集码→保存图片”；[东北石油大学通知](https://jxjy.nepu.edu.cn/info/1331/11335.htm)明确系统可识别学号、院校代码、专业等。院校代码参与机构关联，不代表唯一项目ID，也不能由此认定本原型已接通学信网解密／认证。

## 四、权限、输入与错误恢复

| 情况 | 页面及恢复 |
| --- | --- |
| 首次进入 | 明确扫码意图后尝试相机；无权限或硬件不可用时停在本页，保留相册入口与手动重试 |
| 权限拒绝 | 说明可从相册识别；关闭帮助、上传失败、返回前台均不重复自动申请相机 |
| 打开帮助 | 停止相机流；关闭后只有此前使用且已成功授权的相机模式可恢复；相册模式不切换到相机 |
| 取消系统相册 | 维持原输入方式与页面；系统`cancel`／空文件回调只恢复原状态，不报错 |
| 图片输入 | 扫码页与项目采集码上传统一JPG／PNG／WebP、≤15 MB；不改常用照片工具30 MB限制 |
| 格式、超限、无法读取、没有二维码 | 分别显示实际原因；相册识别失败停在相册模式，可重选；扫码失败可重扫 |
| 非支持码、未关联、项目不唯一、归属不符 | 统一失败抽屉显示真实原因；不随意进入第一个项目、不跟随任意外链；原项目保留 |
| 解析服务异常或12秒超时 | 说明暂无法关联／关联超时，允许重试，不伪造成功或归咎于本人信息 |
| 关闭失败 | 相机模式恢复已授权相机；同一码5秒内不重复触发，防止关闭后立即重弹；相册模式维持静止 |
| 离页、后台、开帮助／文件选择 | 停止相机及手电筒、取消定时读取；代次标记忽略迟到相机、识别与解析结果；返回前台不擅自改变输入方式 |
| 未登录 | 保存5分钟、仅内存的单次交接，走原登录；成功回到目标项目自动打开对应阶段；取消登录停在项目，不强制循环；主动“开始采集”可继续登录 |
| 换账号、项目失效、超时或离开此流程 | 放弃待交接，不把旧姓名、编号、码内容带给新任务。刷新／进程重建不保留内存交接，重新识别；不可把本地恢复能力写成服务端持久化 |

## 五、协议与能力边界

- 浏览器`BarcodeDetector`／随包`jsQR`进行真实二维码图案解码；没有接入学信网解密、名单核验、机构后台或真实登录服务。
- 本地`collectionCodeAdapter.parse`只接受显式`zhipai-demo://`示例；任意字符串、外部链接、未经解析的真实加密码均不能冒充可信码。正式服务接入替换此适配器；解析结果仍须按配置检查机构、项目、认证方式与开放状态。
- 示例院校代码→示例机构→项目的映射位于`createCollectionConfig().codeBindings`。项目内识别限制在原项目；首页未匹配或多个匹配时失败，不显示项目选择。
- 原始码、姓名、学号不写URL或本地持久存储。本人码中的返回字段只是待核对信息；当前`collectionAdapter.match`仍为本地模拟，不表示官方验证。
- 顶部返回来源采用同源页面路径；解析后的码不当作可导航URL。成功仅交接原身份核对流程，不创建订单或提交采集照片。

## 七、验收清单

- 首页、专区、项目内分别验证两类码的去向；机构码不跳过个人码，个人码不重复上传。
- 登录成功／取消、项目跨院校／结束／入口关闭、无关联／多项目时不能误进或建单。
- 帮助两类正文可读，长内容独立滚动，标题与底部固定，详情返回目录，外链打开官方学信档案。
- 相机拒绝后相册可用；帮助关闭、相册取消／失败和前后台切换不反复弹权限；手电筒不支持时不出现无效入口。
- 识别后项目返回、扫码取消、失败重试、系统返回及原项目字段保留连贯；异步返回不污染新任务。
- 沿用17px标题、44px返回与公共抽屉／按钮，首屏及小屏操作可达，真机权限、触摸、读屏及外部App返回仍待验收。

源码／状态／构建结果见实施记录；检查通过不代表用户视觉验收完成。
