# 知拍 V1.4.6 支付恢复、工具示例与消息反馈

更新日期 2026-11-17。规格用于 Web 原型验收及 iOS、Android、鸿蒙交接。原型使用本地交易和测试素材，三端 SDK、后台查款和真机验收待接入。

## 支付渠道

- App 内微信支付打开微信 App 收银台。微信内独立发生的小程序交易使用小程序支付，结果页在具备回跳能力时提供「返回知拍」。[微信支付场景规则](https://pay.wechatpay.cn/doc/v3/merchant/4054257696)
- 中国区 iOS 的电子照片解锁、照片精修及照片换装走 Apple 内购。照片冲印、明信片、邮折和属于 App 外消费的服务走微信或支付宝。专项采集按实际服务交付和平台审核口径确认渠道；原型专项演示使用外部渠道。[Apple 审核指南 3.1](https://developer.apple.com/app-store/review/guidelines/#payments)
- 原型默认按 iOS 演示数字权益，Android 或鸿蒙浏览器可走外部渠道演示。付款按钮附近可选择演示场景，收银台标明演示性质。

## 原单恢复

| 场景 | 当前页面和下一步 |
| --- | --- |
| 发起支付 | 在原业务结算页或付款抽屉选渠道，先保存原订单 ID、账号、订单参数及来源页面，再打开收银台。同一笔订单的发起和查款共用事务锁。 |
| 正常返回、手动切回、重开 | 恢复原业务与原订单。手动切回及重开先自动查款一次，等待期间防止重复点击。后台确认结果才更新交易状态。 |
| 登录失效或切错账号 | 在原业务引导重新登录。登录原付款账号后继续自动查原单。其他账号看到切换账号提示，禁止读取或查询该笔交易。 |
| 弱网、回调丢失或结果未知 | 在原确认位置保留「暂未确认支付结果」和「查询支付结果」，原照片、参数和订单继续有效。仍未知时保留提示，明确未付时再开放继续支付。 |
| 取消、支付失败或拉起失败 | 显示对应结果。用原订单「继续支付」或「重试打开收银台」，保留原输入。 |
| 支付成功 | 冲印、明信片和邮折回原下单结果，邮折后续仍按学生资格审核规则。专项回该任务。电子照片继续解锁和保存，精修、换装继续处理。 |
| 已付但处理或保存失败 | 保留支付状态和原参数。处理失败执行「重新处理」，已有成片时执行「重试保存」。入口继续使用已付原单。 |

正式接口通过一笔业务订单关联渠道交易和所有查询。服务端校验支付结果及账号归属，幂等发放一次权益或启动一次履约。App 持久保存可恢复订单引用与返回位置；重回前台、冷启动和登录恢复均按原订单查款。原型可在同一浏览器重开并恢复最近一次未决返回，保留每笔订单自身的交易状态。

## 常用工具效果示例

七个工具工作页在未选图时分别展示用户提供的 1200×896px 头图，各页同宽并按原图比例显示。点击上方图或底部「选取照片」打开选图抽屉，参数可在各自设置内预选。选入或带入真实照片后显示用户图，精修、换装和更换背景自动做人像检测，冲印校验 5∶7。检测、处理、保存和建单使用用户照片。

照片规格目录使用同系列的全幅浅蓝头图，图内仅展示三张 3D 人像样片。选规格由下方宫格触发。[头图配置](../../src/components/ToolCapabilityPoster.jsx)

| 工具 | 当前页操作 |
| --- | --- |
| 更换背景 | 预选蓝、白、红及浅灰底色，选图并通过检测后处理实际照片。 |
| 照片精修 | 底色选项用于本次精修，完成后可拖动滑杆比较原图与成片。 |
| 照片换装 | 在下方预选男装、女装或童装款式，选图并通过检测后继续。 |
| 修改尺寸 | 设置目标规格，选图后按像素尺寸裁剪。 |
| 格式转换 | 选择 JPG／PNG，按目标格式输出。 |
| 修改大小 | 设置目标 KB／MB 上限，选图后按原尺寸处理。 |
| 照片冲印 | 两项排版独立选择及预览，所选照片通过比例校验后可确认排版。 |
| 照片规格 | 点击三列九项中的规格后选底色，再去拍照或选图。 |

## 消息反馈

公共轻提示沿用深蓝灰底、白字、12px 圆角、14px 字号。在当前导航或固定操作栏上方留 16px，单行约 2 秒、两行约 3 秒。照片删除、丢弃成片和确认收货复用白色居中确认框。持续的字段和支付问题留在相关位置，检测与制作详细原因进入原有上滑抽屉。系统授权和渠道认证由所属系统绘制。登录成功 Toast 是否取消单列待确认。[消息反馈规范](../design/message-feedback-guidelines.md)

## 验收顺序

1. 分别从冲印、明信片／邮折确认页、电子照片结果、精修／换装及专项任务发起支付，核对按钮、价格和结果去向。
2. 在同一业务验证弱网未明、恢复查询、取消后重付、回跳丢失和重开。比对恢复前后的订单 ID、选图和参数。
3. 测试登录失效后分别登录原账号及其他账号。核对其他账号无法查款及看到原订单内容，切回原账号后自动恢复。
4. 核对七个工作页各自的头图，预选参数时头图保持固定。分别点头图和底部按钮打开选图，核对取消回到无图状态，选入或带入真实照片后替换头图。核对照片规格页由宫格打开选色。
5. 核对 Toast 的键盘、安全区和抽屉层级，验证取消删除返回原详情，核对结果页只反馈一次成功。三端另外验证系统权限、渠道回跳和服务端订单的真实结果。
