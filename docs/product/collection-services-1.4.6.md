## 1. 服务中心承担什么

帮助用户自行解决常见采集问题；无法解决时，统一联系知拍客服。涉及姓名、采集资格、院校名册等机构资料问题，由客服协调机构核实处理，用户无需自行判断该找哪一方。

### 已确认的业务范围

- 保留邮件客服，本轮重点完善采集帮助和任务定位。
- 人工咨询统一由知拍客服受理，再协调相关机构，不增加另一套由用户自行选择的机构问题受理流程。
- 任务定位使用采集项目和客服号。有任务时便于提供对应信息；没有任务、尚未完成认证的用户也能咨询。
- 采用第3节九项帮助范围，覆盖从查找项目到异常处理及照片保存。
- 帮助正文和客服邮箱由后台维护，iOS、Android、鸿蒙读取同一份配置；只修改说明或邮箱不需要发布新App，也不触发App强更。
- 服务中心中的通知入口继续使用[已确认的通知规则](collection-notifications-1.4.6.md)，不重复设计消息功能。

## 2. 用户怎样使用

| 情况 | 操作路径 | 产品要求 |
| --- | --- | --- |
| 常见办理疑问 | 进入服务中心，查看相关帮助 | 正文说明该做什么，内容与当前项目规则一致 |
| 看过帮助仍无法解决 | 联系知拍客服，确认后打开邮件应用 | 保留原页面和来源，由用户在邮件应用中编辑、发送 |
| 已有采集任务的问题 | 从原任务客服入口咨询，提供项目名称、客服号和问题 | 沿用原任务，不为咨询再次建任务或付款 |
| 尚无任务、没有客服号 | 直接邮件说明项目及遇到的问题 | 不强制先完成认证、付款或拍照；没有号码不补造号码 |
| 姓名、资格或机构名册问题 | 知拍客服统一受理并协调机构 | 用户通过同一客服渠道沟通，资料由有权限的业务方核实处理 |

客服号用于帮助客服定位记录，不代替身份核验，也不作为任何人访问他人任务的授权。

## 3. 已确认帮助范围与初始正文

九项帮助范围及正文上滑抽屉已确认，下表作为后台初始文案，发布前与实际App和项目规则校对；不代表正式业务原型已经更新。服务中心保留头部和底部菜单，通知入口后为客服入口和九项帮助，正文共用一个滚动区；帮助打开既有上滑抽屉，长正文可完整阅读，关闭恢复列表位置。不增加搜索、分类菜单或咨询记录页。

| 问题 | 初始正文 |
| --- | --- |
| 如何找到需要参加的采集项目？ | 在专项列表中按新生入学、毕业生或行业协会查找，也可以搜索项目名称或采集单位。进入项目后，先核对项目名称、采集时间和要求。未开始或已结束的项目不能直接开始新采集。 |
| 如何获取机构／院校二维码？ | 二维码由组织本次采集的机构或院校提供，通常随采集通知发送。查看已有采集通知，保存的二维码图片可从相册识别，现场二维码可直接扫描。仍未找到时，可联系知拍客服协助核实。 |
| 如何获取学信网图像采集码？ | 使用本人账号进入学信档案，查看本次采集对应学籍的图像采集码，保存完整清晰的图片，再返回知拍识别并核对信息。具体步骤复用现有扫码帮助正文，外部页面以学信网当前界面为准。 |
| 身份信息无法匹配或资料有误怎么办？ | 先核对所选项目、认证方式及输入资料。确认无误后仍无法匹配，或姓名、采集资格、名册信息有误时，联系知拍客服，由客服协调机构核实。不要通过重复创建任务解决资料问题。 |
| 支付后没有继续采集，怎么办？ | 回到原采集任务查看实际付款状态。结果尚未确定时，应先查询原单；仍无法确认时，联系知拍客服核实，避免重复支付。已付任务的制作、审核失败及重拍不重复收费。 |
| 照片制作失败怎么办？ | 进入原采集任务查看失败原因，并按页面允许的方式继续处理。已有任务和付款记录保留，无需重复建任务或付款。无法继续时，提供项目名称和客服号联系知拍客服。 |
| 照片审核未通过怎么办？ | 在原采集任务中查看审核意见，并按要求重新拍摄和提交。实际操作以当前任务状态及项目开放规则为准；项目已结束或无法继续时，联系知拍客服核实处理方式。 |
| 上网失败需要重新拍照吗？ | 先查看上网失败原因并联系知拍客服协调处理。上网失败与照片审核未通过不同，不根据上网失败自行重复采集或再次付款；后续按核实后的处理结论操作。 |
| 采集完成后如何保存照片？ | 在采集记录中打开已完成、提供保存操作的任务，点击保存照片，并按手机提示允许所需权限。保存失败时重试保存或联系客服，不为保存照片重新制作或付款。 |

两类码的详细步骤继续引用[扫码帮助契约](scan-collection-1.4.6.md)，不维护两套有差异的获取流程。扫码帮助的“未收到时如何咨询”文档口径同步为知拍客服协助核实，原型代码仍待同步；二维码来源仍是机构或院校，知拍不替代机构发放资格。

上述文案不补造审核时限、客服响应时间、退款承诺或机构例外权限。帮助说明不能使已结束项目自动恢复办理；采集完成不等于上网完成。

## 4. 邮件咨询与任务定位

### 已确认的共享联系路径（正式业务UI待补齐）

1. 用户在服务中心或任务客服入口点击联系。
2. 打开统一「联系知拍客服」上滑抽屉，展示同一有效客服邮箱；仅在有效任务来源时展示项目名称和客服号，无任务也能咨询。
3. 「复制邮箱」为次操作，「打开邮箱」为主操作；点击「打开邮箱」即为该次外跳确认，不叠加第二层确认。关闭保留来源且不触发外部应用。
4. 用户自行编辑和发送邮件。打开邮件应用、从邮件应用返回，都不能提示为已发送或客服已受理。

当前原型使用邮箱`zpai_service@163.com`和主题「专项采集咨询」，该地址作为初始配置候选，由服务责任方核对可用性后发布；正式端读取后台有效配置，不继续在三端分别写死该地址。不填写虚构联系方式和服务时段。

### 已确认的咨询与恢复范围

- 有任务：方便用户获取项目名称、客服号并描述问题；是否预填邮件正文及预填细节仍需核对，不预填完整证件号或照片。
- 无任务：项目名称、问题描述即可发起咨询，客服号不作为必填门槛。
- 无法打开邮件应用：保留页面，说明未能打开，提供复制客服邮箱后自行联系的恢复方式。个人客服已有复制邮箱能力可参考，不代表专项入口已经接入。
- 邮件回复继续在原邮件渠道完成；本轮不因完善服务中心新增站内工单、客服聊天、咨询状态或处理进度页。

## 5. 当前实现与开发交接边界

### 5.1 后台维护与三端读取（已确认）

| 内容 | 后台维护职责 | 三端职责 |
| --- | --- | --- |
| 帮助正文 | 维护本轮九项帮助的标题、正文与有效内容 | 从共同配置来源读取并展示，不各自维护不同版本的答案 |
| 客服邮箱 | 核对实际服务地址，发布有效邮箱 | 展示、打开邮件和复制邮箱使用同一个有效地址 |
| 两类采集码帮助 | 统一服务中心与扫码相关说明 | 不把不同端或不同入口的旧流程当成另一套规则 |

这是产品数据需求，不是已存在的接口或后台页面。服务端需核对可复用能力，给出内容读取协议、维护权限和有效配置；具体字段、发布生效、缓存更新及失败恢复由技术方案明确。

读取失败应与没有帮助内容区分。拿不到有效邮箱时不能编造或展示未经确认的备用地址；通用帮助和联系不依赖本人采集记录加载成功。修改正文或邮箱属于后台内容维护，App代码变更正式发布仍执行既有强更策略。

### 5.2 原型现状与需落实事项

[服务中心组件](../../src/components/CollectionServices.jsx)当前包含通知入口、四项组件内固定帮助和邮箱联系；[任务客服抽屉](../../src/components/CollectionTaskDrawer.jsx)展示姓名、项目和客服号，可复制客服号，再进入邮箱确认。详情页主卡已删除的复制入口不因此恢复。

以上为当前正常业务实现，不是已确认目标结构完成状态。九项帮助正文抽屉、通知后客服再帮助的顺序、共享邮件联系抽屉及复制邮箱／外跳恢复仍待补齐；[工作区](prototype-workbench.md)仅提供独立任务和邮件反馈样例，不打开真实邮件、不写真实任务，也未接入后台帮助或邮箱配置。

通用客服中的[邮箱复制逻辑](../../src/domain/support.js)仅供复用评估，其旧的个人照片帮助不是本轮专项帮助的最终文案。不得因引用该组件而把个人业务改版自动加入本轮。

需要交给开发核对：

1. 采用本轮确认的帮助正文及维护方式，统一服务中心与扫码帮助的相关口径。
2. 保留邮件确认、取消和来源返回，补齐无邮件应用等异常恢复；通用帮助和联系不依赖本人记录读取成功。
3. 已有任务使用真实项目名称和客服号；查询失败或未生成号码如实显示，不猜测、不泄露他人记录。
4. 明确客服统一受理和协调机构的工作衔接，不以“打开邮箱”代替实际受理，不声称客户端已有机构资料修改接口。
5. 原型浏览器下载不等于原生写入手机相册；实际三端保存、邮件跳转、权限及返回需按真实版本验证。

## 6. 后续交付与验收

### 业务范围已确定，后续需完成

- 由产品和服务责任方校对后台初始帮助正文、核实邮箱，按当前App和项目规则发布。
- 由开发落实后台维护及三端读取，明确数据生效、缓存更新、读取失败和无有效配置时的恢复；当前原型仍是固定内容，没有内容管理接口。
- 核对任务咨询是否预填邮件正文及预填细节；九项帮助抽屉、共享联系抽屉和长正文结构已确认，正式业务按确认结构实施，沿用[DESIGN](../../DESIGN.md)和[反馈规范](../design/message-feedback-guidelines.md)。后续发生实质结构变化时再更新样图，不重复确认已批准结构。

### 产品验收要检查什么

- 未登录、未认证、无任务和任务读取失败时，通用帮助与咨询入口仍可用。
- 九项帮助内容可完整阅读，两类码说明一致；没有把上网失败引导为无条件重拍。
- 从任务发起咨询时定位到原任务，无任务时不强制补造客服号。
- 取消邮件无外跳；确认才打开；打开失败有恢复方式，返回不丢原页面。
- 后台修改帮助正文或邮箱后，三端通过约定更新机制读取到同一份有效内容，无需发布新App；展示、复制和邮件跳转使用一致的邮箱。
- 姓名、资格、名册问题统一由知拍客服受理协调，不要求用户自行挑选机构受理渠道。
- 客服联系不重复创建任务、触发付款或改变审核结果；实际发送和机构处理不伪造成功。

这些是验收要求，尚未执行原生测试或产品体验验收。正常业务UI、正文发布校对、邮件预填细节及后台接入尚未完成；本轮工作区隔离演示不替代该交付。本次材料不分派工程师工期，不增加岗位评分表，也不表示后台内容管理或客服系统已开发。文档路径及格式检查与实际功能验证分别记录，不以规则／结构确认替代页面和原生验收。
