# 专项采集服务中心

页面地址：`/?page=collection&view=services`。由专区底部「服务中心」进入，帮助参与者自行解决采集疑问，无法解决时联系知拍客服。本人资料、资格与机构名册问题由客服统一受理并协调机构，用户无需先判断找哪一方。

## 服务中心头部与导航

顶部为「服务中心」「采集帮助 · 客服支持」和客服主题配图，返回退出专区回知拍首页。底部保留专项列表、采集记录、服务中心和扫码；通用帮助和联系不依赖本人采集记录加载成功，未登录、未认证、无任务也能咨询。

当前正常业务内容顺序是通知入口、四项帮助、邮件客服。已确认目标顺序为通知入口、客服入口、九项帮助，共用一个正文滚动区并保留头部及菜单；正式业务UI仍待补齐。本页不新增搜索、分类菜单、咨询记录或站内工单。

## 通知中心入口

入口显示「通知中心」「系统通知与项目动态」，点击进入通知中心并记录服务中心为来源，返回恢复本页位置。本页不堆本人采集通知列表，也不提供通知演示按钮；通知历史、未读与公告演示只在通知中心使用。

通知及记录职责不同：前者保留发生过的消息，后者展示本人任务最新状态。服务帮助不会生成通知、修改审核或解除项目开放限制。

## 联系知拍客服

当前联系卡显示客服邮箱`zpai_service@163.com`和「联系」，点击先打开邮箱确认。没有任务可直接描述项目和问题；有任务时优先从原任务客服入口提供项目与客服号，不为咨询再次认证、建任务或付款。

客服号只帮助定位，不授予访问权限；没有号码或查询失败如实显示，不猜造号码。当前邮箱为初始配置候选，正式发布需服务责任方核对有效性，并由后台提供统一配置，不虚构时段、响应时限或退款承诺。

## 帮助内容

正常业务目前是四项组件内固定帮助：找项目、认证资料、审核未通过、完成后保存，点击在列表内展开／收起。**已确认目标是以下九项，每项打开现有上滑抽屉，固定标题、长正文可滚动，关闭恢复原列表位置；目标结构与正文尚未全部进入正常业务。**

| 帮助标题 | 正文应让用户知道什么 |
| --- | --- |
| 如何找到需要参加的采集项目？ | 在分类或名称／机构搜索中找项目，核对名称、时间与要求；未开始／结束不能新办 |
| 如何获取机构／院校二维码？ | 码由机构院校提供，查看采集通知或已保存图片；未找到由知拍客服协助核实 |
| 如何获取学信网图像采集码？ | 本人登录学信档案，选择本次学籍，保存完整清晰采集码后回知拍识别 |
| 身份信息无法匹配或资料有误怎么办？ | 先核对项目、方式与输入，仍有问题由客服协调机构；不重复建任务 |
| 支付后没有继续采集，怎么办？ | 回原任务查付款，结果未定先查原单，已付失败重拍不重复收费 |
| 照片制作失败怎么办？ | 查看原任务原因及允许操作，保留任务与付款，无法继续提供项目／客服号咨询 |
| 照片审核未通过怎么办？ | 查看审核意见，在项目允许时重拍提交；结束或不能继续时联系客服 |
| 上网失败需要重新拍照吗？ | 查看原因并由客服协调，不自行重复采集或再次付款 |
| 采集完成后如何保存照片？ | 打开提供保存动作的完成任务，按权限保存；失败重试保存，不重做或重付 |

两类码的详细步骤复用扫码帮助，不维护不同入口各自一套流程。扫码旧代码「找负责人」口径仍待同步到客服统一协调，码的提供方仍是机构。帮助说明不等于学信网解密、官方资格校验或真实照片已保存。

## 邮件联系

已确认共享「联系知拍客服」抽屉：显示同一有效邮箱，有有效任务来源才带项目和客服号；次操作「复制邮箱」、主操作「打开邮箱」。点打开即为该次外跳确认，不再套第二个确认；关闭不外跳，保留来源。

正常业务当前仍是取消／打开邮箱确认，完整共享抽屉、复制与外跳失败恢复待补齐。无法打开时应留在本页，提供复制邮箱后自行联系；打开或返回邮件应用都不能提示已发送、已受理。是否预填邮件正文及细节待核对，不放完整证件号或照片。

## 帮助及邮箱配置读取

九项正文和客服邮箱已确认由后台统一维护，三端读同一有效配置；仅改内容不发新App，也不触发强更。当前没有真实内容管理接口，不能说已支持后台发布。

读取失败与无内容区分，拿不到有效邮箱不补造备用地址；通用咨询不依赖本人任务读取成功。具体读取协议、权限、缓存更新与发布生效尚需技术方案明确。依据：[服务完整契约](../collection-services-1.4.6.md)、[扫码契约](../scan-collection-1.4.6.md)、[服务组件](../../../src/components/CollectionServices.jsx)、[任务客服抽屉](../../../src/components/CollectionTaskDrawer.jsx)。本文未进行真实邮件、三端或视觉验收。
