# 知拍 · 我的订单与订单详情执行规范

版本：1.4.6；更新：2026-10-22；状态：四种交易状态及冲印四段履约已按用户确认的结构样图实施，待用户验收。

本模块供用户核对购买内容、金额、付款／退款事实及冲印履约信息。当前为 React 高保真移动 Web 原型，供 iOS、Android、鸿蒙还原逻辑；支付、退款及物流未接入真实服务。

[设计规范](../../DESIGN.md#统一订单中心) · [隔离交互样例](orders-1.4.6.html) · [本轮状态调整记录](../reviews/orders-20261022/status-model.md) · [已确认结构样图](../reviews/orders-20261022/status-approved-structure.png) · [三端交付](../../HANDOFF.md)

本轮覆盖此前「待付款／付款确认中／已支付／已关闭」订单中心分类及相关付款底栏。原订单、原业务付款／查款恢复仍保留；不修改首页、工具来源规则或照片制作流程。

## 1. 入口与职责

个人中心「我的订单」默认全部类型、全部状态。汇总当前账号电子照片、照片冲印、照片精修、照片换装、专项采集五类交易；排除 fixture、匿名、外账号及旧兼容支付占位。删除相册照片不删除订单，已购未交付照片仍在原工具／相册恢复。

订单只包含交易与冲印必要履约，不提供客服、照片放大、排版查看、下载、编辑、继续制作、业务跳转或采集任务入口。缩略图仅供识别购买内容。冲印详情的确认收货是履约操作，不触发制作或改变付款金额。

仅展示交易状态 `paid／failed／refunding／refunded`。待付款、已关闭、取消、付款结果未确认及其他未知记录隐藏，不删除记录，不将未知付款认作失败。旧链接进入隐藏状态详情时显示「未找到该订单／请返回订单列表查看」，不开放付款或查款窗口；在原业务继续恢复同一笔订单。

## 2. 列表布局与操作

从上到下：系统安全区 → 52px导航「我的订单」→ 横向业务类型 Tab → 交易状态单选胶囊 → 票据列表。前四项沿用固定蓝白半透明磨砂顶部，无外发光；票据上滑从其背后经过。无底部菜单、状态统计、笔数或搜索。

| 区域 | 内容及规范 | 行为 |
| --- | --- | --- |
| 导航 | 17px居中标题、44px白色圆底返回，右侧等宽空槽 | 返回来源，默认个人中心 |
| 类型 Tab | 全部、电子照片、照片冲印、照片精修、照片换装、专项采集；48px高、13px字，无边线和外层卡片 | 手指横滑、单选；中间尽量居中，首尾贴真实边界，下一项露边；重复点击不移动 |
| 状态 | 全部、支付成功、支付失败、退款中、已退款 | 单选取交集，「全部」不是第五种交易状态；不增加冲印物流筛选 |
| 状态外观 | 12px／18px，24px可见胶囊、至少44px触控；全部蓝灰、成功绿、失败红、退款中琥珀、已退款蓝灰 | 选中以同色底、细描边及600字重共同区分；窄屏／大字号换行，不挤压文字 |
| 票据 | 白底、16px圆角／内边距、12px间距、左右16px；无阴影或点击转场 | 整卡直接进入同一单层详情 |
| 表头 | 左服务名15px／600，右交易状态12px，同基线；下方浅蓝灰虚线与半圆缺口 | 名称最多两行，状态不换行 |
| 购买区 | 本单只读缩略图、13px摘要、17px／600金额、12px已记录规格和时间 | 完整等比照片，缺图／解码失败为中性占位；不借用其他订单照片 |

两类筛选相互保留，取交集。切换明确筛选回列表顶部；详情返回保留类型、单个状态、类型条横向位置、列表滚动与原卡片焦点。切换账号清除原账号位置缓存。卡片不做缩放、展开或共享元素动画。类型 Tab 支持方向键、Home／End；状态为 radio 组及可见焦点。

URL 仍用单值 `type=print&status=paid`；新状态值为 `paid／failed／refunding／refunded`。旧 `pending／verifying／closed`、非法或逗号状态回退全部；`q` 不再参与筛选。旧冲印已支付详情链接保持单层订单详情。个人中心订单数量仅统计可展示交易，不再显示「N笔待付款」。

## 3. 购买内容文案与数据来源

| 来源 | 标题及购买信息 |
| --- | --- |
| 电子照片 | 证件照制作 · 普通版／精修版；照片规格、文件像素、背景色取本单购买快照 |
| 精修 | 照片精修；记录的照片规格及底色 |
| 换装 | 照片换装；记录的照片规格及实际服装 |
| 当前冲印 | 背胶模切证件照；二寸4张＋一寸8张 · 1版／二寸8张 · 1版，读取版式快照 |
| 专项采集 | 实际项目名称、机构与采集人；不重复采集审核状态 |

参数只出现一次。缺版本时仅显示「证件照制作」；可选规格／底色缺失时省略，不写内部「版本未记录」。有记录的像素可展示，但不能由金额、像素推断版本或物理尺寸。必要金额、费用、地址、时间缺失仍如实说明，不补造0元、退款方式或物流时间。

新电子照片保存 `purchaseSnapshot`；精修保存 `repairBackground` 及购买底色。历史订单 ID、金额、文件和已记录参数不改写。专项关联照片和机构目前不都是不可变交易快照，真实后端需提供完整快照，不能宣称已接入。

## 4. 详情布局

普通导航「订单详情」下16px起始，同一张白色长票据，16px圆角／内边距，无嵌套白卡、额外阴影或页外大状态卡：

1. **交易概览**：左「交易状态」13px、右状态14px／600；其下左金额标签13px、右金额22px／650。支付失败用「订单金额」；其余用「实付金额」，退款金额另列，不能把原价当退款金额。
2. **购买内容**：只读本单照片、服务名及已记录参数。
3. **费用明细**（冲印）：冲印费、配送费及确有记录的历史附加费。当前每单¥19.80＋运费¥10.00，历史读取本单金额，不重定价。
4. **退款信息**（退款中／已退款）：退款中显示「申请退款金额」，已退款显示「已退金额」；申请时间、退款完成时间及方式有记录才显示。金额须有实际非负整数分记录，缺失显示「金额待确认」，不默认全额。不新增申请退款按钮。
5. **冲印进度**（仅冲印且有实际进度）：右侧回显当前阶段，下方只读四段进度及一句状态说明，与交易状态独立；不提供模拟推进按钮。
6. **配送信息**（冲印）：收货人、电话、地址及确有记录的承运方／运单；不重复交易或制作状态，不改地址。
7. **订单信息**：原编号、创建时间，实际支付时间／方式有记录才显示。

购买内容后的第一组使用虚线及两侧6px半圆缺口，其他组使用1px #EEF2F7实线；分组前20px、线下16px。组标题15px／600、字段13px、行间12px，标签左对齐、值及金额右对齐。进度圆点8px、1px连线、12px文字，当前项蓝色和600字重及 `aria-current="step"`；无跳步操作。

编号超过20字符时前8位…后8位，提供就地「展开完整编号／收起编号」。复制44px触控，复制完整原值，就地「已复制」2秒及读屏播报；失败展开原值，提示长按复制。运单同理。

## 5. 交易状态与冲印履约矩阵

| 状态值 | 展示 | 判定与操作 |
| --- | --- | --- |
| paid | 支付成功 | 明确已付，制作失败或审核失败不能变成支付失败；一般无底栏 |
| failed | 支付失败 | 最近一次明确支付失败；展示有记录的原因，不虚构原因，不在订单新增付款入口 |
| refunding | 退款中 | 已付原单存在退款处理事实，展示实际申请金额；不开放确认收货 |
| refunded | 已退款 | 已付原单存在已退款事实，展示实际已退金额；不开放确认收货 |

独立冲印进度：

| 状态值 | 文案 | 进入条件 |
| --- | --- | --- |
| producing | 制作中 | 付款已确认，等待安排或正在制作；旧producing／printing合并到此阶段 |
| shipped | 邮寄中 | 已发货、运输途中 |
| delivered | 待签收 | 已送达、等待用户确认 |
| received | 已签收 | 用户确认收货；历史completed兼容为已签收，不补造用户确认时间 |

仅支付成功且进度 delivered 的冲印单显示固定底部主按钮「确认收货」：48px高、14px圆角、15px字并避让安全区。点击沿用居中确认窗：「确认已收到照片？」／「确认后，本订单将标记为已签收。」／「暂不确认」「确认收货」。取消不改状态；提交中禁止重复点击、关闭和返回；成功持久化原单后撤掉底栏并提示「已确认收货」，交易仍为支付成功。未送达、退款中／已退款、外账号、离线不得确认；写入失败留在确认窗，保留待签收可重试。

后台物流送达与用户确认是两个独立事实。退款不自动撤回、推进或伪造履约进度，仍显示最后实际记录；原型不新增退款申请、售后或退款推进业务。

### 数据与迁移契约

- 各来源保留原业务 `status` 及原订单 ID；新增 `paymentResult: {status, at, reason?}` 保存最新支付事实。status 为 paid／failed／verifying／cancelled／unpaid，不直接作为订单筛选项。
- 发起付款／查款先存 verifying，明确成功存 paid，明确失败存 failed；取消存 cancelled、明确未付存 unpaid，未知继续 verifying。原业务可以维持 pending 供原单重试。只有 pending 且最新事实 failed 才显示支付失败；旧冲印 attempt=failure／failed 为明确失败兼容，其余旧待付款不能批量改成失败。
- 原单已付且有 `refund: {status: refunding|refunded, amount?, requestedAt?, refundedAt?, method?}` 时进入退款态。amount 为整数分；method 仅实际 original／wechat／alipay 等已定义值，不推断原路退回。无退款事实不生成退款单。
- 冲印 `fulfillment: {status: producing|shipped|delivered|received, shippedAt?, deliveredAt?, confirmedAt?}` 独立持久化；旧status producing／printing→producing，shipped→shipped，completed→received，不构造历史时间。新付款进入 producing；确认收货写 received、confirmedAt，并保留兼容业务status=completed。
- 付款／退款／履约三类事实均由同一原订单关联，存储快照不能丢弃新字段。账户、原金额、文件及参数不变；重复回调、确认和恢复不得重复收费、建单、写成片或追加确认事件。
- 原业务恢复：电子照片原解锁窗口查款；专项原付款抽屉查款；精修／换装在原工具查询同一订单后恢复；冲印重新进入原确认流程弹出查款窗口，保留草稿。隐藏订单中心记录不能让查询回到该中心形成死路。

## 6. 空态、异常与可访问性

| 情况 | 文案与恢复 |
| --- | --- |
| 无可展示交易 | 暂无订单／购买的服务将在这里展示；仅有隐藏草稿也使用此空态，不删除草稿 |
| 筛选无结果 | 暂无支付失败订单等对应状态；「查看全部订单」重置类型与状态 |
| 数据读取中 | 正在读取订单；不把临时0当作确定数量 |
| 部分来源失败 | 保留已读列表，「部分订单未能加载／重新加载」 |
| 全部来源失败 | 订单暂时无法加载／重新加载 |
| 隐藏、不存在或外账号订单 | 未找到该订单／返回订单列表；不泄露账号或交易信息 |
| 离线 | 网络不可用，请恢复连接后重试；已读事实可看，确认收货禁用 |
| 确认失败 | 说明未保存，保留待签收和原金额，可再次确认 |
| 图片失败 | 中性照片占位；不影响交易信息可读性 |

仅列表／详情正文滚动，固定顶部、底栏和弹窗操作区；长名称、地址、编号、大字号不能覆盖动作。弹窗焦点约束，Escape／系统返回先关闭，忙碌不可中断；页面在弹窗后 inert。类型与状态键盘可操作，状态不只靠颜色表达。

## 7. 验收入口与边界

[正常本地订单](http://127.0.0.1:4180/?page=orders&type=all&status=all&back=%2F%3Fpage%3Dmy)。启动 `npm run dev` 后打开[隔离交互样例](orders-1.4.6.html)，复用正式组件与CSS，提供四种交易状态、四段冲印进度、缺图、长编号、空态、离线和加载异常。示例仅改内存，不读取作者订单，不发起付款／退款／物流请求，刷新复原；不是额外生产入口。

验收顺序：四状态单选及类型交集 → 隐藏记录与原业务恢复 → 同票据交易／退款／履约分区 → 待签收取消确认／成功／失败重试 → 返回保留筛选及位置。源码／服务模拟／存储回归不能代替用户实际视觉验收。当前按项目约定未自动操作浏览器、截图或运行UI自动测试；iOS／Android／鸿蒙需分别验证原生材质、安全区、动态字号、读屏、系统返回及真实支付／退款／物流接口。
