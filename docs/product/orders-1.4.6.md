# 知拍 · 我的订单与订单详情执行规范

版本：1.4.6；更新：2026-10-22；状态：已按用户确认方案实现，等待用户验收。

本模块用于核对购买内容、金额、付款事实及冲印配送信息。当前为React高保真移动Web原型，供iOS、Android、鸿蒙还原产品逻辑；本地模拟付款不能作为真实扣款、云订单或物流能力。

## 1. 入口与职责

个人中心「我的订单」默认全部类型、全部状态。兼容已有业务链接传入的订单类型和来源；旧冲印详情／结果链接进入统一的单层详情。删除搜索，不读取旧q筛选。订单不提供客服、照片放大、排版查看、下载、编辑、继续制作或进入采集任务；缩略图只是购买内容识别，不是看图入口。

五类来源：电子照片、照片冲印、照片精修、照片换装、专项采集。仅汇总当前账号明确归属的记录，排除fixture样例和旧兼容支付占位。删除相册照片不删除订单，已购买但未完成的照片由原业务／相册恢复。

## 2. 列表布局与操作

从上到下：系统安全区 → 52px导航「我的订单」→ 横向业务类型Tab → 付款状态单选胶囊 → 票据列表。前四项共用固定的蓝白半透明磨砂顶部；列表滚动视口覆盖整页，初始票据在顶部下方8px起始，上滑时从顶部背后经过。无全局底部菜单，不显示状态统计或「共N笔」。

| 区域 | 内容与尺寸 | 操作 |
| --- | --- | --- |
| 导航 | 17px居中标题，44px白色圆底返回，右侧等宽空槽 | 返回来源，默认个人中心 |
| 顶部材质 | 包含系统安全区、导航和两层筛选；无外发光或外扩阴影，蓝白半透明底、内部弱弥散及背景模糊，末端在自身范围内收尾 | 票据透出模糊轮廓，不干扰文字和点击；顶部高度随安全区、提示及文字换行测量。减少透明效果或不支持模糊时用实底回退 |
| 类型Tab | 无外层白卡、外框及所有分隔线；48px高、13px字、下一项自然露边；全部、电子照片、照片冲印、照片精修、照片换装、专项采集 | 独立横滑、单选；中间项尽量居中、首尾贴边；选中仅蓝字／600字重，不加数量 |
| 付款状态 | 全部、待付款、付款确认中、已支付、已关闭；12px字，24px可见胶囊、至少44px触控；蓝灰／琥珀／蓝／绿／灰低饱和浅底 | **单选**，选择另一项替换当前项；重复点击当前项保持选中。选中加深同色底、描边与字重，不只靠颜色区分 |
| 票据 | 白底、16px圆角、16px内边距、12px卡间距，左右各16px | 整卡直接进入同一订单详情，无点击缩放、展开或返回转场动效 |
| 表头 | 左服务名15px/600、右付款状态12px；下方1px浅蓝灰虚线，两端6px半圆缺口 | 名称最多两行，状态不换行 |
| 购买信息 | 左56×78px真实照片，右13px摘要，金额17px/600固定右侧；其下12px已记录尺寸与时间 | 完整等比照片，仅用于识别；缺图或解码失败使用中性占位，不独立点击 |
| 对齐 | 页面外边16px、票据内容32px；文字与时间共用左边，金额与状态共用右边 | 参数或名称变长时票据自然增高，状态胶囊窄屏／大字号换行，不压缩文字 |

两项筛选取交集：例如「照片冲印」与「已支付」只显示已支付冲印单。切换类型保留所选状态；切换状态保留类型；任何明确筛选变化回到列表顶部。类型使用语义Tab及左右方向键，状态使用radio组及方向键，均支持Home／End与可见焦点。类型横滑只移动Tab条，不切换整页。重复点击当前类型不移动标签、不重置结果。类型条首尾不设置空占位；402px逻辑宽度显示约4.35项（每项至少80px），以邻项露边表达后续内容。

详情返回保留类型、单个状态、列表滚动及类型条横向浏览位置，并恢复原卡片焦点。首次进入或刷新按URL对当前类型作有边界的初始定位；全部从左端开始，中间项尽量居中，末项贴右端。横向缓存仅用于当前页面会话内往返，不宣称浏览器刷新后保存用户手动横滑位置。付款使原单移出当前筛选时，保留筛选和有效滚动范围，回到更新后的列表，不强制跳到已支付，也不定位到别的卡片。切换账号后不复用上一账号焦点／滚动缓存。

URL继续使用`type=print&status=paid`等单值参数；不引入状态集合、数量或搜索条件。无效状态（包括逗号多状态）回退全部，兼容既有单状态链接。旧类型抽屉入口及渲染已删除。

电子照片优先展示已记录文件像素，工具优先展示已记录物理尺寸；缺失不补造，不由文件像素反推规格。按用户票据参考保留服务标题与购买信息分区，不引入客服电话、再买一单、看图或业务恢复操作。

## 3. 购买内容文案与数据来源

| 类型 | 标题 | 列表摘要 | 详情内容 |
| --- | --- | --- | --- |
| 电子照片 | 证件照制作 · 普通版／精修版 | 二寸 · 蓝底 | 照片规格、文件尺寸、背景颜色 |
| 精修 | 照片精修 | 本单记录的规格 | 照片规格 |
| 换装 | 照片换装 | 本单规格 · 男装衬衫等实际服装 | 照片规格、所选服装 |
| 当前冲印 | 背胶模切证件照 | 二寸4张＋一寸8张 · 1版／二寸8张 · 1版 | 版式与数量各出现一次；费用在同一凭据分组 |
| 专项采集 | 实际项目名称 | 机构名称 · 采集人姓名 | 同一摘要，不重复采集审核状态 |

以上是有快照时的示例，不是补造历史数据的模板。缺少版本时标题仅显示「证件照制作」，不显示「版本未记录」；列表没有规格／底色时使用「电子照片」摘要，有记录的像素继续展示。详情只显示有记录的可选规格／底色字段，缺失不另占一行；费用、金额、收货地址、创建时间等交易事实缺失时仍明确标识，不能暗示已确认。不能由413×579px推断旧单为二寸，也不能由¥9.80推断精修版。旧工具photo.spec为明确记录，可原样显示；旧电子订单仅有像素时不显示不存在的规格或底色。

新电子照片在创建订单时记录`purchaseSnapshot`：specName、mm、pixels、backgroundName；版本、金额和输出仍绑定同一原订单。新工具记录实际photo.spec，不用工具默认输出预设替代输入尺寸。历史订单ID、费用、参数和已购文件不重写。已知背胶版式才称背胶模切，历史未知版式保留原版式描述及费用。专项当前照片取关联记录，既有机构／采集人并非完整交易时快照；后端交付应提供不可变购买内容及缩略图快照，不能宣称已接入。

## 4. 详情布局

导航「订单详情」后依次为：

1. **交易概览**：收在同一张票据顶部，不另设页外状态卡。第一行左「付款状态」13px、右状态14px/600；第二行左金额标签13px、右金额22px/650。右侧与后续字段对齐。待确认显示「付款结果尚未确认，请先查询，勿重复付款。」。
2. **购买内容**：56×78px只读照片、完整服务名及上述参数。同一卡片内每项只出现一次，不重复列表摘要和逐项参数。
3. **费用明细**（仅冲印）：冲印费、配送费；确有历史附加套餐才展示附加费。当前¥19.80＋¥10.00＝¥29.80，但详情读取本单费用，历史数据不按当前价格改写；未记录费用不伪造0元。
4. **配送信息**（仅冲印）：收货人、电话、地址；付款后如实展示待发货／已发货／已签收；承运方、运单有记录才展示。只读，不在订单改地址，不展示制作信息。
5. **订单信息**：完整原编号、创建时间；支付时间及方式确有记录才显示，不补造。

以上所有分组收拢为一张白色票据，导航下16px起始：16px圆角、16px内边距，无额外阴影。概览与购买内容之间为1px #EEF2F7细线；购买内容后第一组（冲印为费用，其他为订单信息）使用1px #D6DFEC虚线及两侧6px半圆缺口，其他分组沿用实线。分组上方20px、下方16px留白，不嵌套白卡。分组标题15px/600、字段13px，标签左对齐、值右对齐；行间距12px。金额和日期等宽数字。已支付与已关闭不留固定底栏，自然滚动和留白。

编号20字符以内完整显示；长编号默认前8位…后8位，轻文字「展开完整编号」在当前卡片展开，可「收起编号」，不弹窗。复制按钮44px，始终复制完整原值；本按钮显示「已复制」约2秒并读屏播报。失败显示「请长按订单编号复制」并呈现完整值供长按，运单同理；切换订单清除反馈。

## 5. 付款状态与操作矩阵

| 归一状态 | 概览 | 金额标签 | 底部操作 |
| --- | --- | --- | --- |
| pending | 待付款／暖色 | 待付金额 | 继续付款；仅冲印同时取消订单 |
| verifying | 付款确认中／蓝色 | 订单金额 | 查询付款结果 |
| paid | 已支付／绿色文字 | 实付金额 | 无 |
| closed | 已关闭／灰色 | 订单金额 | 无 |

冲印producing、printing、shipped、completed均归已支付；cancelled归已关闭。制作、审核、保存、签收等业务状态不参与付款筛选。

五类继续付款均打开公共上滑抽屉「确认付款」：服务及原金额、微信／支付宝单选、固定主按钮「确认付款 ¥X.XX」。不创建新订单，不处理或保存照片。请求中「正在确认…」，方式和重复提交禁用，关闭／遮罩／返回均不能中断。完成留在同一详情：

- 成功：关闭抽屉、显示已支付、付款时间／方式，提示「付款成功」。
- 明确未付款：保留原待付款单，提示「付款未完成，订单已保留。」。
- 未知／响应超时：原单verifying，只能查款，不重复付。原型响应最多等待15秒后转待确认；存储错误保留现有可确认事实，不伪报成功。

查询使用同一抽屉「查询付款结果」，说明「付款结果待确认，查询期间无需再次付款。」；按钮「查询付款结果」。确认已付后更新原单；明确未付恢复待付款；未知显示「付款结果仍待确认，请稍后再次查询。」。原型结果选择折叠在「原型演示」，与业务信息区分。

仅冲印pending可取消：居中确认「取消这笔订单？」、说明「取消后本订单将关闭，尚未付款。」、按钮「暂不取消／确认取消」。确认关闭原单并留在已关闭详情；失败保留订单可重试。付款待确认、已付和已关闭不提供取消或退款入口。当前旧冲印规格／价格待付款单仍不可按新价付款，明确提示取消后按新规格重新下单，保留旧金额。

返回顺序：活动覆盖层 → 当前详情 → 筛选列表 → 来源页面。刷新／恢复时依据原订单持久状态；未知付款先查原单，不自动重发付款。原生端需接入服务端幂等接口及生命周期处理，本地延时不代表真实支付超时协议。

## 6. 空态、异常与可访问性

| 情况 | 文案与恢复 |
| --- | --- |
| 无购买记录 | 暂无订单／购买的服务将在这里展示 |
| 筛选无结果 | 暂无待付款订单等对应状态；「查看全部订单」同时重置类型与状态 |
| 数据读取中 | 正在读取订单；不将临时0当作确定总数 |
| 全部来源失败 | 订单暂时无法加载／重新加载 |
| 部分失败 | 保留已读列表，顶部「部分订单未能加载／重新加载」，不显示笔数，不能暗示全部读取成功 |
| 订单不存在或不属本账号 | 未找到该订单／返回订单列表 |
| 离线 | 网络不可用，请恢复连接后重试。已读取记录可看，付款和查款禁用 |
| 图片缺失或加载失败 | 默认中性照片占位，订单和交易信息仍可见 |

焦点可见、屏幕阅读器具有状态／按钮名称，复制反馈用live region；标题和操作固定，仅列表／抽屉正文滚动。长地址、长项目名、完整编号及手机字号放大不遮挡动作；平台安全区用原生实际值替换Web基准。

## 7. 验收入口与边界

正常订单：[本地预览](http://127.0.0.1:4180/?page=orders&type=all&back=%2F%3Fpage%3Dmy)。隔离样例：启动`npm run dev`后打开[交互样例](orders-1.4.6.html)，复用订单React组件及CSS，在独立文档内提供全部状态、缺图、长编号、读取失败、离线、付款成功／未付／待确认演示；只改内存，刷新复原，不读取用户账号／IndexedDB、不运行真实适配器，不是生产订单入口。

验收顺序：类型横滑及居中 → 状态单选与交集结果 → 票据列表与详情层级 → 展开编号 → 付款失败与查询 → 冲印取消 → 无点击转场、返回保留筛选与滚动。正常页面的实际付款持久化由域测试验证，交互样例只用于评审UI和状态文案；两者不可互相替代。iOS／Android／鸿蒙还需分别验收系统返回、动态字体、照片加载、离线恢复、安全区以及真实支付回调。
