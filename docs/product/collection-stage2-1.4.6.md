# 知拍 V1.4.6 第二阶段产品需求

整理日期：2026年11月3日。本文件为网站内可读取的本阶段需求全文，页面说明按相关章节同步。

适用范围：iOS、Android、鸿蒙客户端，以及配套服务端、测试与产品验收。

原型参考：本次登记11.3-3，准确提交由`prototype/2026/11.3-3`解析，实际推送结果见[交付台账](../releases/prototype-deliveries.md)；输入基线为11.3-2（`d4cf3a5`）。原型用于说明交互和业务规则，不代表正式接口或三端原生功能已经实现。

## 一、版本目标与范围

本阶段继续以服务机构专项采集为主，补齐用户在采集过程中的消息触达、问题处理及登录体验，覆盖三块：

| 模块 | 本阶段内容 |
| --- | --- |
| 通知 | 通知中心、历史与已读、重要手机推送、项目／系统公告、全局强制更新 |
| 服务 | 九项采集帮助、任务定位、邮件客服、后台统一维护帮助及邮箱 |
| 登录 | 验证码主流程、上次成功号码、密码次入口、平台第三方登录、返回与恢复 |

不包含微信／支付宝小程序，不新增在线客服聊天、工单、咨询进度或退款申请。个人证件照、常用工具、冲印和订单的独立改版不自动纳入。

原有项目、认证、采集前付款、拍摄制作、提交审核、采集记录、失败原因及重拍流程继续保持。同一已付采集任务的失败恢复与重拍不重复收费。

## 二、通知

### 2.1 通知中心

通知中心提供“全部、系统、项目、采集”筛选；全部只是筛选项，不是第四种消息类型。

列表展示标题、时间、来源或项目、摘要及未读标记。仅显示当前账号有权查看的消息。历史消息独立保留，不随任务新状态被覆盖。

读取中、无消息、筛选无结果及读取失败分别处理，失败提供重试。返回时保留筛选和列表位置。本轮不增加一键已读、删除或清空。

### 2.2 通知分类及去向

| 类型 | 产生方式 | 点击去向 |
| --- | --- | --- |
| 采集通知 | 根据后台确认的本人采集结果生成 | 原采集任务最新详情，以最新状态决定允许操作 |
| 项目通知 | 后台人员选择项目、人群并填写内容发布 | 先阅读完整公告，按需点击查看对应项目 |
| 系统通知 | 后台人员按受影响平台或人群发布 | 普通公告阅读全文；版本更新按适用的全局升级规则处理 |

项目与系统公告正文展示类别、标题、来源、发布时间和完整内容。目标失效或无权访问时说明原因，不跳到其他项目或任务。

### 2.3 采集结果触发与手机提醒

| 结果 | 站内通知 | 手机系统提醒 |
| --- | --- | --- |
| 制作失败 | 生成 | 重要消息 |
| 审核未通过 | 生成 | 重要消息 |
| 采集完成，项目无需上网 | 生成 | 重要消息 |
| 采集完成，项目还需上网 | 生成 | 不提醒，等待上网结果 |
| 上网完成 | 生成 | 重要消息 |
| 上网失败 | 生成 | 重要消息 |

制作中、待提交审核、审核中不单独发通知，继续在任务和采集记录展示。采集完成不等于上网完成；上网失败不自动要求重拍、重付或重新提交。

手机提醒受系统权限和平台能力约束。通知中心中的消息生成、推送发送、手机送达、用户查看及已读分别记录，不能混为同一结果。

### 2.4 前后台提醒

| 用户场景 | 处理规则 |
| --- | --- |
| 正在查看对应任务 | 直接更新页面结果，不重复叠加提醒 |
| 正在其他普通页面 | 重要消息显示可点击轻提醒，普通消息安静进入通知中心 |
| 正在拍摄、付款或提交 | 不插入提醒、不抢焦点，消息保留在通知中心 |
| App在后台或未打开 | 按重要消息与人工发布规则进行手机系统推送 |

手机通知仅使用简短标题和查看引导，不展示姓名、证件号、照片或详细失败原因。用户关闭系统通知不影响站内查看和采集办理。

### 2.5 历史、去重与已读

- 同一任务先审核未通过、重拍后采集完成，两条消息都保留当时内容与时间。旧消息仍进入任务最新状态，不能恢复已经失效的重拍、付款或提交动作。
- 只有成功打开对应任务或公告正文后才标已读；收到或滑掉推送、轻提醒出现／消失、任务页面自动更新不算已读。
- 登录取消、正文读取失败、目标打开失败不算成功查看。已读消息仍可再次阅读。
- 同一次结果重复回调、查询或刷新只生成同一条消息；重试产生的新一次结果保留新消息。
- 新状态已取代旧状态时，尚未发出的过时提醒停止，站内历史保留。
- 登录、重装或同步历史时不集中补推旧消息。推送重试处理原消息，不新建重复通知。

### 2.6 后台人工发布

项目通知由后台选择项目、接收人群，填写标题和正文后发布。系统公告按受影响的平台或人群发布，不默认全员广播。

两类人工公告均提供“同时发送手机提醒”，默认关闭；关闭不影响站内发布。本轮不增加按项目开放、截止时间自动发送通知。

### 2.7 全局强制更新

**每次本平台、本渠道正式发布用户可获取的新App版本后，所有旧版都必须更新才能继续使用。** 不采用只对低于最低支持版本的用户强更的方案。

1. 各端分别判断当前渠道的真实安装版本，不使用另一平台版本、产品迭代号或原型日期版本进行判断。
2. 仅开发完成、提审或审核通过但尚未发布，不提前拦截用户；必须确保对应渠道已有可获取的新包。
3. 启动及从后台返回时查询适用版本。已更新用户不再拦截，高于目标的内部包不要求降级。
4. 提示“发现新版本”、更新内容及“去更新”，不提供取消、稍后或跳过；用户可通过系统离开App。
5. 点击去更新不等于安装完成。从更新渠道返回后核对实际安装版本，仍旧版继续提示，符合要求才恢复业务。
6. 正在拍摄、付款或提交时，先保全照片、输入及已发起交易，到可恢复的安全节点再强更，不丢任务或重复收费。
7. 更新入口打不开或更新失败时保留任务并可重试，不能提示成功或自动绕过。
8. 是否收到推送、是否已读、是否关闭通知权限，不影响强更判断。仅修改帮助正文、邮箱、后台服务或推送原型不触发App强更。

通知权限／推送渠道、版本查询接口及实际安装结果均需真实接入。工作区“恢复默认”和结果选择只供演示，不作为正式App允许跳过更新的功能。

## 三、服务中心

### 3.1 页面职责与结构

服务中心帮助用户自行解决常见采集问题；无法解决时，统一联系知拍客服，由客服协调机构。

页面沿用专项采集设计，保留返回、标题及专项导航。正文依次为通知中心入口、客服入口、九项帮助。学信网图像采集码条目直接打开指定H5教程；其他八项正文通过公共上滑抽屉展示，长内容可完整阅读，关闭恢复原列表位置。

### 3.2 九项帮助

| 帮助 | 正文必须说明的内容 |
| --- | --- |
| 如何找到采集项目 | 按分类或项目搜索查找，进入项目先核对名称、时间与要求；未开始／已结束不能直接启动新采集 |
| 如何获取机构／院校二维码 | 由组织采集的机构或院校提供，可查看通知、保存图片或现场扫描；未找到联系知拍客服协助核实 |
| 如何获取学信网图像采集码 | 直接打开[学信网图像采集码获取教程](https://www.zhipai.com.cn/h5/bystxcj.html)；服务中心与扫码帮助使用同一地址，不再维护本地重复教程 |
| 身份信息无法匹配或资料有误 | 核对项目、方法及输入，仍不匹配由知拍客服协调机构，不通过重复建任务解决 |
| 支付后没有继续采集 | 回原任务核对实际付款，结果未知先查原单，避免重复付款 |
| 照片制作失败 | 查看原任务实际原因与恢复操作，保留已有任务及付款，不重复建单或收费 |
| 审核未通过 | 查看实际审核意见，在项目允许范围内重拍和提交；项目已结束或无法继续时联系客服 |
| 上网失败 | 查看原因并联系知拍客服协调，不自动重拍、重付或重提 |
| 完成后如何保存照片 | 从提供保存操作的完成任务导出，按实际系统权限处理；保存失败重试，不重新制作或付款 |

帮助不补造审核时限、客服响应时间、退款承诺或机构例外权限。服务中心与扫码不维护两套不同的获取码流程。

### 3.3 任务定位与邮件联系

1. 服务中心及任务客服入口使用同一“联系知拍客服”上滑抽屉。
2. 有有效任务时展示项目名称、客服号；无任务、无号码或本人记录读取失败，仍可使用通用帮助和咨询。
3. 客服号仅用于协助定位，不代替身份授权，不补造号码或读取他人资料。
4. 抽屉提供“复制邮箱”和“打开邮箱”。点击打开即本次外跳确认，不叠加第二层相同确认；取消不打开外部应用。
5. 用户在邮件应用自行编辑、发送。打开应用或从邮件返回不等于发送成功、客服受理或问题解决。
6. 打不开邮件应用时保留原页面和任务，提供复制有效邮箱的恢复方式；复制失败不得显示已复制。
7. 姓名、资格、名册及上网问题统一由知拍客服协调机构，不让用户自行选择机构受理渠道。

不默认把完整证件号或照片带入邮件。是否预填邮件正文及具体内容仍需核对。

### 3.4 后台统一配置

九项帮助的标题、正文与客服邮箱由后台维护，三端读取同一份有效配置。展示、复制与外跳使用同一个邮箱。

仅修改帮助或邮箱不要求发布新App。读取失败、无内容及无有效邮箱要区分，不展示虚构备用地址；通用帮助不依赖本人任务读取成功。

当前原型中的`zpai_service@163.com`仅为候选初始地址，正式发布前由服务责任方核实。后台发布、生效、缓存刷新与异常恢复须与开发对齐。

## 四、登录

### 4.1 主流程

手机号→明确同意用户协议及隐私政策→获取验证码→验证→登录成功回原业务。未注册号码验证成功后注册。

取消运营商一键登录；密码作为次入口，平台第三方入口统一置底。有效会话再次进入主登录入口时恢复原业务；失效后重新验证。

### 4.2 上次成功号码

只记录最近一次真正成功登录的号码，脱敏显示“上次登录号码”，用户可更换。

- 仅输入号码、发送验证码、失败或取消不覆盖成功历史。
- 记住号码不代表免验证或已经登录，每次新登录协议初始未勾选。
- 更换号码清除旧验证码、挑战、倒计时及重置授权。
- 普通退出清会话但保留号码；注销清理与该账号匹配的记住号码。

### 4.3 验证码与密码

验证码校验当前号码、用途及有效期，登录、绑定、重置用途不得串用。错误／过期留在当前阶段并给出重输或重发方式，倒计时不能延长服务端有效期。

当前原型以5分钟有效、60秒重发作流程参照，正式时效和频控需与服务端对齐，不把常量验证码123456接入正式App。

密码登录保留手机号、显示／隐藏密码及忘记密码。未设置密码引导验证码登录。找回密码先验证对应手机号，重置要求8—32位且含字母和数字、两次一致；完成回密码页重新登录，不自动建立会话。

### 4.4 平台第三方登录

| 平台 | 保留入口 |
| --- | --- |
| iOS | Apple、微信 |
| Android | 微信 |
| 鸿蒙 | 华为、微信 |

先明确同意协议再授权。授权凭据需真实校验，授权成功不等于手机号已关联；需要绑定时仍验证本人号码。取消清理临时上下文，不伪造登录成功。

### 4.5 返回与恢复

验证码返回号码步骤并保留同次有效输入；密码页返回主入口；找回／重置回密码入口。主入口返回为取消，回原业务；弹层先关闭。

登录成功后重新校验当前账号对原目标的权限，不自动付款、提交或创建采集任务。来源无效、外部或循环时回个人中心；原生端使用受控业务目标，不照搬任意Web返回链接。

忙碌时防重复提交；离开或更换号码后旧异步结果不得覆盖新流程。账号切换后不能显示前账号的消息、任务或验证状态。

### 4.6 单屏体验

登录及关联验证页面应在手机可用高度内完整呈现，不允许页面或表单滚动。输入、协议与主操作保持可见可达；三端分别验证短屏、软键盘、系统返回和字号放大，不能仅靠固定Web画布判断通过。

正式协议正文、短信、第三方SDK、账号与会话、密码重置和注销服务均需接入；本地账号、模拟授权和浏览器平台识别仅为原型能力。

## 五、接口与配套交接

下表规定产品需要的数据含义及结果，不指定已有API地址、JSON字段、SDK或技术供应商。

| 能力 | 需要对齐的内容 |
| --- | --- |
| 通知列表／正文／已读 | 稳定消息标识、类别、内容、时间、接收人、关联目标、历史、排序／翻页、已读写入与同步 |
| 采集事件与人工发布 | 五类结果、办理／重试批次、去重依据、人群范围、人工手机提醒开关、发布权限 |
| 手机推送与打开目标 | 设备与账号归属、平台通道、权限、发送重试、登录后权限校验及来源恢复 |
| 版本更新 | 平台／渠道、真实正式版本及构建、可获取与生效状态、更新说明／入口、安全节点与安装后核验 |
| 服务内容 | 九帮助、有效邮箱、维护发布、内容更新和缓存、读取失败及无有效配置恢复 |
| 登录与账号 | 短信挑战／用途、注册登录、密码／重置、第三方与绑定、会话失效、正式协议及既有安全业务 |

仍须落定：有效强更策略与离线查询失败的衔接、无法安装新版设备的兼容处理、发版后自动更新消息的生成机制、实际客服邮箱与帮助发布校对、邮件预填细节及正式接口测试环境。已确认页面结构与业务规则不再列为待确认。

## 六、验收要点

| 模块 | 必测场景 |
| --- | --- |
| 通知 | 五类结果和三个不通知的过程状态；上网节奏；同次去重与新次历史；已读条件；人工受众；前后台避让；登录／账号／目标失效 |
| 强制更新 | 本端本渠道有可获取新包；未发布／已新版／高版本不误拦；安全节点；入口失败、仍旧版、真实更新后恢复；照片与原单不丢失 |
| 服务 | 九项帮助及两类码一致；长文抽屉；有／无任务；邮箱共享配置；取消／外跳／复制失败；客服统一协调机构 |
| 登录 | 首次／回访；协议；错误／过期／换号；密码／找回；三端第三方；取消和来源恢复；迟到结果；退出／注销；单屏真机 |

开发自测与联调后进入测试，再进行产品体验验收；修复后回归受影响场景。真实推送、平台权限、邮件外跳、登录凭据、键盘与升级安装须使用实际环境验证，不以演示按钮或本地常量代替。

## 七、当前原型实现与正式接入边界

本次本地实现将通知历史／已读和完整公告接入正常通知页面，将九项帮助与共享邮件联系接入正常服务中心；原型历史存于本浏览器并按账号隔离。登录沿用已确认A结构，密码重置一并保持单屏布局。外层文档与实际页面、关键抽屉联动。

通知中心和服务中心可在左侧切换隔离样例；强制更新始终归属顶部「全局演示」，提供入口失败、返回仍旧版及模拟安装完成。演示不写真实业务数据、不发送系统推送、不打开真实邮箱或商店。正常业务的打开邮箱则使用当前有效配置，通过用户明确点击发起外跳；浏览器无法可靠证明邮箱应用已打开或邮件已发送。

当前没有真实后台内容管理、消息发布／手机推送、短信与第三方授权、版本检查或安装服务。前后台推送及渠道发布由正式三端与服务端实现，原型的场景和规则检查不等于设备能力已接入。
