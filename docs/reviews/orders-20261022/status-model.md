# 订单四种交易状态与冲印履约调整

日期：2026-10-22。状态：按用户明确确认的方案和[结构样图](status-approved-structure.png)实施，用户已要求提交并推送，具体版本以 Git 记录为准；未发布站点，实际视觉与交互仍待用户验收。

## 目标与已确认范围

订单中心只展示「支付成功／支付失败／退款中／已退款」，保留「全部」单选筛选。隐藏其他状态但不删除原业务记录，保留付款及查询恢复；取消、超时、制作失败不算支付失败。

冲印详情另设「制作中→邮寄中→待签收→已签收」。邮寄中指已发货运输途中，待签收指已送达等待用户确认。仅支付成功且待签收提供二次确认收货。退款只显示已存在事实，不新增申请退款流程，不自动改写物流。

沿用 Impeccable 的 Operate 原则、知拍既有磨砂顶部、单选胶囊、票据、轻线分组、导航及确认窗规范；未重做品牌、字体、卡片或照片功能。

## 实施与流程串联

- `order-status.js`：单一四状态投影及独立冲印阶段。最新付款事实与业务status分开，明确失败才可见；旧冲印明确失败attempt兼容，未付款及未知不推断。退款要求原单有已付事实，退款金额从原记录读取。
- 原电子制作、专项付款、精修／换装、冲印及共用付款适配器同步写入最新 `paymentResult`。原单ID、文件、版本、参数、费用不变。失败重试覆盖本次付款结果，未知先查询，不重复扣款。
- 原工具可查询同一笔未知付款；重新进入同服务或恢复其草稿时保留原照片与冻结参数，先查询再继续，不导向已隐藏的订单中心记录。查询优先于新图检查或付款，不新增扣款。
- 冲印未知付款保留原草稿、回到确认流程并打开原查询窗口；物流模拟送达停在delivered，不再自动成为已签收。确认收货校验当前账号、最新交易和履约状态，成功写原单received／confirmedAt和一条事件；失败可重试，重复确认不重复追加事件。
- 冲印存储快照保留 `paymentResult／refund／fulfillment`；老producing／printing归同一制作阶段，老completed保留已签收事实，不伪造历史确认时间。
- 列表、详情和隔离样例共用正式组件：交易状态、实际退款金额／时间／方式、冲印四段只读进度分组。详情只有符合条件的确认收货底栏，无付款／查款／取消／退款申请、照片查看或客服入口。
- 个人中心订单数量仅统计四种可展示交易，不再提示待付款数量。类型横滑、单选交集、详情返回横纵位置及无卡片转场保持。

## 三端与原型边界

Web仅本地模拟；真实支付、退款回调、物流送达、服务端幂等收货确认均待接入。退款示例不会生成或修改作者本地订单，真实数据没有退款事实时不补造。原生端应采用[订单产品契约](../../product/orders-1.4.6.md)的独立状态、权限及恢复关系，接入服务端权威状态，而非按客户端延时推进物流。

验收可打开[正常订单](http://127.0.0.1:4180/?page=orders&type=all&status=all&back=%2F%3Fpage%3Dmy)与[隔离状态样例](../../product/orders-1.4.6.html)。重点确认四状态胶囊、交易与物流的区分、退款事实排版、确认收货二次确认与返回位置。
