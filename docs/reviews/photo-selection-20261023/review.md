# 七业务选图与底部操作统一

日期：2026-10-23。范围：冲印、照片精修、照片换装、照片裁剪、更换背景、格式转换、修改体积。用户已明确确认[结构样图](structure-approved.png)并授权实施；代码与文档已更新，实际页面待用户验收。本轮未提交、推送或部署。

## 已确认的页面职责

| 状态 | 当前页面与操作 | 后续行为 |
| --- | --- | --- |
| 无有效照片 | 第一步、小白熊与原说明，底部单个「选取照片」 | 打开原选择抽屉 |
| 已选择照片 | 第一步、照片及文件信息；底部「更换照片＋下一步」 | 不自动检测、处理或跳步 |
| 选择同一张／另一张 | 仍显示已选状态；同图保留设置，新图清除相关旧产物与可重建草稿 | 等待明确下一步；取消保留当前输入 |
| 需要人像检查 | 下一步才触发；检查中禁用操作 | 通过自动继续；未通过留第一步，可换图但不能继续；异常可重试 |
| 冲印 | 下一步才校验5∶7比例，不限制照片内容 | 符合到排版；不符合先固定比例手动裁剪，确认后带实际裁剪文件到排版 |
| 其他免费工具 | 下一步才准备预览并进入设置 | 保留原参数、处理及设备交付流程 |
| 从照片详情进入 | 直接显示第一步的当前照片及双按钮 | 顶部退出返回完整原详情路径，下一步仍由用户点击 |

## 视觉与Impeccable检查

沿用知拍现有蓝白规范，依据已确认结构实施，无新增视觉方向。照片保持5∶7浅灰contain预览及250px宽度上限，规格在照片下方12px，以12px辅助文字完整换行。旧照片下方换图文字／图标已删除，预览组件只负责展示。

七业务共用`PhotoSelectionActions`：未选时满宽单按钮；已选时左侧中性描边「更换照片」与右侧知拍蓝「下一步」，宽度2∶3、间距12px、同高48px、14px圆角、15px字。底栏左右16px、上12px，底部沿用设备安全区。保留44px以上触控区、键盘焦点、禁用状态、操作组语义及减少动态效果支持。后续设置页、步骤条、导航与完成页不重排。

代码与静态结构检查通过；未自动打开浏览器、截图或运行自动UI测试。实际视觉、触摸、不同屏宽、系统字体缩放与读屏仍待用户及原生端验收，不将源码取值视为视觉验收结论。

## 逻辑实现与原有保护

- 六工具`accept`只接收候选，所有来源统一`choosingPhoto`；点击`primary`才运行原检查或准备预览，不再需要带图入口专属标记。第一步确认不会隐式付款、生成付费结果或保存照片。
- 冲印带图进入及抽屉选图均保留选择阶段；点击`nextLayouts`才按比例分流。原图不变、裁剪产物贯穿排版与下单。直接入口的原比例保护保留。
- 取消选择、失败读取不丢当前候选；异步迟到响应不覆盖新入口。需要重选时只在第一步底部操作；后续通过原「上一步」回到选图。
- 原订单恢复是独立场景。待查款继续查询同一订单，已付订单继续原处理／保存，不能用新候选替换旧订单照片或重建付款。已付款保存失败复用产物重试，原有价格、底色、交付去向保持。
- 照片来源规则本轮不扩展：换装「仅知拍相册」是独立已确认、待代码实施项，当前仍开放手机来源；已在产品文档明确，不宣称已完成。人像检查仍为原型选择演示，不执行真实识别；付款和物流亦为本地演示。

## 用户验收路径

1. 从首页进入七个业务，未选时底部只有「选取照片」。抽屉确认一张后仍是第一步，照片下方没有换图操作，底部变为「更换照片＋下一步」。
2. 点击更换照片，取消保留原图；选择同一张或另一张都不提前检测／跳步。再次点击下一步才继续。
3. 精修、换装、更换背景演示未通过，确认仍在第一步，左侧可换图、下一步不可点；异常可重试；通过自动进入后续，精修仍必须选底色。
4. 冲印用符合／不符合5∶7的照片分别点击下一步：进入排版／固定比例裁剪；裁剪确认后两版预览均使用新文件。回到选图再换一张仍等待下一步。
5. 相册照片详情带图进入六工具均为已选第一步；顶部返回原照片详情。后续上一步回选图时照片、有效参数及双按钮仍在。旧订单不重复收费、保存或替换输入。
