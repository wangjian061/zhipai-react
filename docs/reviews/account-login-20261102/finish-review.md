# 登录流程完成审查

日期：2026-11-02。审查依据：当前源码、已确认的 A 结构合同、服务端静态渲染与状态测试。未操作浏览器、截图或运行 UI 自动化；结构样图不是实际页面截图。

## 1. Direction / fidelity

源码符合已确认的 A：单一手机号入口进入验证码步骤，移除欢迎卡及运营商一键登录，密码作为次入口，第三方方式位于底部并按平台分配。继续使用知拍蓝白背景、品牌资产、系统字体、圆形返回按钮与共享按钮规范，没有建立新的视觉体系。用户追加「登录页适配手机屏幕高度，不滚动」后，保留 A 的区块顺序，只统一收紧留白并按屏幕内部高度分配空间。

## 2. Craft floor

文字层级、表单分组、错误与演示验证码提示、禁用状态和键盘焦点样式均有明确实现。新登录表单不再套用任务卡片。占位文字已改用现有深蓝灰 #526782，在白色输入框上满足 4.5:1 对比度要求；保留既有减弱动态效果支持。实际字形、计算后间距、页面溢出和视觉观感未经画面验收。

## 3. Interaction / responsiveness

成功登录后才记住号码；号码遮蔽不建立会话。更换号码会清除验证码挑战与重置授权，退出或离开登录流程清理临时数据及同意状态。验证码错误、过期、重发、改号返回、密码错误、重置、第三方绑定取消和原业务返回均有状态路径。验证码进入时聚焦，弹层保留 inert、焦点约束及关闭后焦点恢复实现。

第三方方式只出现在手机号与密码入口，验证码步骤保持单一任务。登录主内容已取消滚动；品牌与标题的间距统一收紧，底部方式通过弹性空白定位。保留原字号、44px 次操作与 48px 主按钮，没有隐藏内容或缩小文字。所有登录步骤共用系统状态区预留。

独立按当前 CSS 层叠与已知内容推算高度：设备内部逻辑画布固定 402×874；状态区 62px，导航 52px，内容上留白 16px，下留白 34px，内容可用高度为 **710px**。设备外壳随窗口整体缩放，不因此改变内部布局预算。

| 代表状态 | 推算所需高度 | 相对 710px 预算 |
| --- | ---: | ---: |
| 密码页，无反馈，包含底部第三方入口 | 约 640.2px | 余约 69.8px |
| 密码页，单行错误或重置成功提示 | 约 678.3px | 余约 31.7px |
| 验证码页，同时有演示验证码提示与错误 | 约 575.9px | 余约 134.1px |

上述是源码尺寸推算，依赖当前文案保持预计行数，不能替代实际排版测量。`overflow:hidden` 只能取消滚动，本身不是内容完整适配的证据。原生键盘、系统字体放大、实际换行、安全区、焦点移动和真实短信／OAuth 未验证，不承诺任意原生环境都能单屏容纳。

## 4. Material findings

审查发现的三项已按当前源码复核修复：

1. 默认 welcome 登录页仍命中旧沉浸式页面例外，导致返回按钮进入系统状态区。现已移除该例外与失效的欢迎页样式，所有登录步骤恢复正常状态区预留。
2. 白色输入框的旧占位色对比度为 4.36:1，低于 4.5:1。现已在登录范围改用 #526782。
3. 单屏追加审查发现：密码重置成功提示原先会与之后的错误密码反馈同时保留，预计总高约 716.4px，超过 710px 内容预算。现已在新密码登录尝试开始时清除旧成功提示；测试覆盖错误密码后提示清除，避免用隐藏溢出来掩盖被裁切的第三方入口。

当前审查范围未发现其他应阻止交付验收的实质流程或布局问题。追加修改后独立重跑账号状态／静态渲染测试：12 项全部通过。构建及旧账号／采集流程通过由实施者另行记录，不将其视为画面批准。
