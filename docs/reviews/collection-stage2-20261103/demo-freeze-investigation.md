# 左侧演示卡顿排查

日期：2026-11-03。

## 现象与检查范围

用户反馈通知中心点击左侧本页演示后，整页卡顿、点击无反应。本地4180服务持续响应，首页及入口模块HTTP200，服务端无CPU占用异常。

本次另行获得授权：只读查看当前页及错误，再仅点击左侧「默认列表」与「恢复默认」复现；未点击手机业务，未写账号、任务、订单或支付数据。此授权不扩展为以后默认浏览器操作权限。

## 发现与修复

账号SSR测试使用默认Vite依赖缓存，与持续运行的开发服务共用`node_modules/.vite`。排查时开发缓存目录缺少正式deps目录／metadata，仅残留多个临时优化目录，服务仍引用旧依赖版本路径。部分旧哈希请求能由服务缓存响应，不能凭缺失文件推断每个请求都失败。

已将账号测试改为独立临时cacheDir，关闭测试HMR、WebSocket和文件监听，结束后清理自己的缓存；重启4180服务并重新生成开发依赖缓存。未修改业务UI、演示规则或用户数据。

## 验证与结论边界

- 账号10项源码／状态／SSR检查通过。
- 测试前后开发依赖metadata内容摘要一致，测试不再改写该缓存。
- 授权实点「默认列表」成功显示隔离通知列表；「恢复默认」成功回原通知页，释放演示并恢复触发者焦点。
- 实点采样以空闲为主，没有持续重复渲染热点或新增阻断异常。
- 控制台另有既存`enterkeyhint`属性命名警告，当前证据不支持将其判定为卡顿原因，本轮未顺带修改。

已证实并修复测试与开发服务共用缓存的问题；原始卡死未再次复现，未取得当时的异常堆栈，不能断定缓存冲突是唯一根因。其他未授权演示选项与业务页面未自动遍历。没有提交、推送或部署。
