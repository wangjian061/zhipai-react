# 我的订单：照片识别与排版实施记录

日期：2026-10-21。依据：用户确认A，执行真实照片、删除查找、typeset排版与delight细节方案。本轮实现待用户验收；Git交付以提交历史为准，本轮不包含站点部署。

## 最新规则

照片用于识别购买内容，订单仍只办理交易。本轮覆盖此前[交易边界记录](transaction-boundary.md)中「服务图标／不含照片／保留搜索」三项约定；付款状态、操作范围、配送事实与业务侧权益恢复规则保持。

| 范围 | 已实现 |
| --- | --- |
| 列表与详情 | 共用56×78px真实缩略图，浅灰承托、6px圆角、完整等比显示；无照片放大、下载、编辑或业务跳转 |
| 照片来源 | 电子照片使用本单所购文件；精修／换装优先成片、未产出用本单输入；冲印使用本单裁剪后输入；专项使用关联采集记录当前照片 |
| 缺图与加载失败 | 相同尺寸的中性照片轮廓占位，不显示业务图标，不借用其他订单或示例人物，不隐藏订单 |
| 查找移除 | 删除右上入口、搜索输入、状态和过滤逻辑；旧q不影响列表且后续导航不再传播；「查询付款结果」保留 |

| 反馈 | 卡片按压只变浅底色、不缩放；复制编号／运单后按钮就地显示「已复制」约2秒，读屏同步反馈；失败就地提示长按复制 |
| 空态 | 当前筛选使用「暂无待付款订单」等对应说明；有其他订单时提示切换状态或类型；无订单时才说明购买后展示 |

专项缩略图是关联记录当前照片，不宣称为交易时不可变照片快照。所有金额、订单编号、付款状态及购买版本仍来自原交易记录。照片识别仅使用本地Blob，尚未接入云端缩略图服务。

## 上下步衔接

1. 个人中心或原有订单入口进入统一列表，按当前账号过滤来源，不混入无归属或样例数据。
2. 列表点整卡进入交易详情，缩略图本身没有独立操作；不存在重新引入看图层的路径。
3. 返回恢复筛选与位置。旧链接q不会让订单被隐藏；付款、查询、取消和已支付无业务底栏的原规则不变。
4. 图片加载前后的尺寸固定；照片变化时不闪现上一单图片，Object URL随变化或卸载释放。图片不可用不影响交易操作。
5. 原工具与相册的已购结果恢复继续有效，照片缩略图不承担交付入口。
