# 制作失败分类与恢复检查

日期：2026-10-20。用户确认将「照片制作失败／服务不可用」纳入本轮。继续使用已确认的失败抽屉与 Impeccable 规范，本地实现，未提交或发布。

## 当前规则

| 结果         | 类型依据                                                                     | 用户看到的内容                                                             | 底部操作     |
| ------------ | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------ |
| 制作成功     | 正常制作结果                                                                 | 进入既有只读成片与解锁流程                                                 | 保留原有操作 |
| 照片制作失败 | 明确的 `PHOTO_MAKING_FAILED`，保存 `failureKind=photo`                       | 「制作失败」，直接展示实际原因；无原因时提供照片调整说明                   | 返回调整     |
| 服务不可用   | `MAKING_SERVICE_UNAVAILABLE`；超时、中断、渲染及未知技术错误也归入 `service` | 「暂时无法制作」，说明稍后再试、无需更换照片；不将技术异常描述为照片不合格 | 返回         |

原型结果选择改为三个纵向选项：「制作成功／照片制作失败／服务不可用」。仍在约5秒制作等待后显示，背景锁定、不可取消，不使用专用测试网页或URL指定结果。

两种制作失败复用浅红结果区、深红图标与标题、优先展示实际原因及固定蓝色恢复按钮；白色辅助区继续展示原图与输入保留说明。仅照片检测拒绝展示检测明细，制作失败不混入检查清单。

关闭、遮罩、Escape与底部恢复操作继续进入同一返回链路：保留原图、尺寸和底色，清理失败类型及旧检测证明，回到确认页。重新开始仍要重新检测；失败不生成可解锁结果、收费订单或专项成功回传。

## 旧草稿兼容

失败类型由明确字段决定，不通过原因文字猜测。旧草稿缺失或带未知类型时，同时归为服务异常并使用中性说明「本次制作未完成，请稍后再试。」；直接渲染未知类型也采用相同说明。明确为photo／service的实际原因保持。

这避免历史文案中的「更换照片」与新服务异常提示中的「无需更换照片」同屏冲突。

## 用户验收

在正常制作流程中先选择「检测通过」，等待制作后分别选择「照片制作失败」和「服务不可用」。确认两者标题、原因与恢复按钮对应，返回仍保留原图和设置，重新开始可继续到成功结果。

实际颜色、纵向选项排版、长原因滚动、安全区、触摸及读屏体验仍待用户验收。
