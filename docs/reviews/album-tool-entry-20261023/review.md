# 相册照片详情 → 六工具第一步

2026-10-23。用户确认「进入第一步 → 展示当前照片、允许更换 → 点击下一步 → 原流程继续」，顶部返回原照片详情，现有布局与样式保持。本轮本地实施，待用户验收；未提交、推送或部署。

## 原因与实现

详情的六个工具入口通过 `openPhotoTool` 触发公共 `toolStudio.enter/start`。旧实现立即调用接图逻辑，开始人像检查或免费工具预览，由状态推导直接进入第二步。原先测试也把该跳步行为视作预期，已改为最新确认契约。

带图入口现在只接收候选，并保留 `entrySelectionPending` 与第一步展示状态；不会立即检测、标准化、渲染、打开付款或创建订单。点击下一步后才消费该意图，精修、换装、背景使用原检查流程，通过自动继续；裁剪、格式与体积使用原预览和设置流程。照片精修第二步仍须选择底色，不自动预选。首次候选确认前改选同一张或另一张均不提前运行；取消换图或读取失败保留原候选，用户仍可用原照片继续。

已付款原单恢复维持原状态，不被新候选覆盖。同服务若已有待查款记录，新入口仍先展示候选，点击下一步后使用原单照片和参数恢复查询，不创建重复订单。异步加载结果只属于当前入口任务，迟到结果不覆盖较新的工具。普通选图抽屉的主动确认、后续上一步、完成后再处理和交付目的地维持原规则。

## Impeccable 与视觉边界

本轮为 Operate 模式下的流程修正，沿用已确认知拍规范；页面结构与样式保持，不新增视觉方案、页面或组件。复用现有照片预览、步骤条、「更换照片」与固定「下一步」。没有修改页面组件或CSS。未自动打开浏览器、截图或运行自动UI测试；没有生成最终效果图。源码／状态检查不能替代用户实际视觉、触摸、读屏及 iOS、Android、鸿蒙验收。

## 用户验收

从相册打开一张照片详情，分别点击六项工具：先看到第一步、当前照片和「更换照片／下一步」；不自动出现检查结果或处理。取消或更换照片后仍停在第一步。点击下一步后依原工具流程继续，检测失败留在第一步；顶部返回原照片详情。旧订单查询恢复与已付款结果不得重复收费。
