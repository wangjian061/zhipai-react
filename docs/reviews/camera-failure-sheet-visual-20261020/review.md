# 检测未通过与制作失败 · 抽屉视觉修订

日期：2026-10-20。范围仅为用户确认的两种失败抽屉；沿用 Impeccable 及知拍既有样式。当前为本地修改，未提交或发布。

## 已完成

| 区域 | 当前展示 |
| --- | --- |
| 固定标题 | 左侧28px深红状态图标，与18px加粗短标题「检测未通过／制作失败」同色；右侧保留44px关闭区 |
| 结果区 | 标题及正文开头使用局部浅红背景；先说明当前阶段，再直接展示本次实际原因，不增加查看详情操作 |
| 辅助区 | 白底，后置56×78.4px原图与输入保留说明；检测未通过再展示检测明细，通过项灰色、失败项深红；制作失败不混入检测清单 |
| 固定底栏 | 知拍蓝底白字「返回调整」，自身定义按钮颜色，修复Portal脱离页面祖先后蓝色样式失效的问题 |
| 长内容 | 原因保留换行、不截断，仅正文滚动；标题和操作区固定。缺少原因时明确提示返回后重新开始 |

两种失败共用结构，但分别表达「无法开始制作」与「本次制作未完成」。原照片及参数保留，原因已包含保留说明时不重复展示相同提示。失败图标、文字与背景共同表达结果，不单独依赖颜色。

检测中、短暂通过、检测服务异常仍走原展示分支；检测异常的重新检测按钮同步获得必要的Portal颜色修复。场景选择、自动继续、制作结果选择、关闭与返回、付款保存等业务行为保持。

## 独立收尾复核

独立审查结论：源码范围通过，无新增必改项，可进入用户验收。复核确认失败配色仅作用于两种失败状态、实际原因优先、主按钮不依赖Portal外祖先、长内容具备滚动布局，以及关闭、遮罩、Escape继续进入原恢复链路。未发现本次范围内的阻断问题。

设计规范与产品结构说明同步情况见[documentation.md](documentation.md)。本轮没有新增位图。

## 用户验收

1. 在「证件照制作」点击「开始制作」，选择「多人照片／动物照片／无人像」，查看检测未通过：应先看到失败状态和实际原因，再看到原图及检测明细。
2. 选择「检测通过」，制作等待结束后选择「制作失败」：应直接展示制作原因，不出现检测清单。
3. 点击「返回调整」后仍保留原图、尺寸与底色；重新开始继续使用原场景选择和检测流程。
4. 实际首屏观感、图标对齐、长原因触摸滚动、设备安全区及读屏播报仍待验收。
