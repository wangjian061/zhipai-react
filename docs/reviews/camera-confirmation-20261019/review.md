# 照片确认页来源适配整改

日期：2026-10-19。用户已确认方案；已实现，待实际画面验收。

[产品规则](../../product/camera-confirmation-1.4.6.md) · [交互式结构说明](../../product/camera-confirmation-1.4.6.html)

## 问题与结果

原页面把拍照、手机相册、知拍相册均描述为“拍摄效果”，返回和“重新拍摄”均进入相机，造成来源与操作不匹配。

现统一为「确认照片」「确认使用这张照片？」「请确认人像清晰、正面无遮挡」。拍照来源保留「重新拍摄」；手机相册来源重新打开系统选图；知拍相册来源复用已有选图抽屉。用户后续纠正：顶部返回只做页面导航，拍照回相机，相册回原来源页，禁止打开选图；仅底部「重新选择」打开选图。订单中心原有返回优先规则保持。

同时修正系统相机文件输入原先被记为手机相册来源的问题；系统拍照与网页实时拍照均保存camera来源，刷新恢复后仍能正确分流。

## oil-ui-pro规范复核

- 用户任务：确认当前照片并开始制作；来源差异只体现于重新获取照片的动作，不增加新的决定或步骤。
- 保留现有布局、深蓝标题、辅助灰说明、主次按钮、照片展示与失败原因抽屉；删除“满意这次拍摄效果吗？”等来源限定文案。
- 既有按钮反馈、选图层过渡和照片内扫描动效保持；未添加装饰性动效。
- 不自动操作浏览器或截图，未进行独立视觉评审，不给视觉分数。源码规范复核与实际视觉验收分开记录。

## 前后流程与检查

| 范围 | 验证 |
| --- | --- |
| 拍照 → 确认 → 返回 | 实时与系统拍照均记录camera来源；次按钮及返回进入拍摄；两种相册来源的顶部返回不会触发选图 |
| 手机相册 → 确认 → 重新选择 | 取消、无效文件保持原图、会话和页面；确认新图清理旧输出及付款状态 |
| 知拍相册 → 确认 → 重新选择 | 打开选择层不改变照片；新图仍带回原工具／专项任务上下文 |
| 刷新恢复 | 会话记录保留phone／finished来源，恢复后按钮仍显示「重新选择」 |
| 异步竞争 | 老选择层回传不覆盖新会话；制作已开始时忽略迟到的选图解码结果 |
| 制作与失败 | 在当前页制作，失败保留照片、原因抽屉和重试；通过后继续原编辑或专项回传流程 |
| 原有能力 | 相册保存、原图、订单付款与解锁、扫码隔离、照片扫描几何及生命周期契约通过 |
