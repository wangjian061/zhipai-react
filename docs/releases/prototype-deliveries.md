## 后续登记格式

每次正式交付按以下字段新增记录：

| 字段 | 填写要求 |
| --- | --- |
| 原型版本 | 月.日-当天序号 |
| 完整日期 | YYYY-MM-DD，北京时间 |
| 目标需求范围 | 如 V1.4.6；注明本次改动是否纳入该迭代 |
| 交付分支 | 实际分支 |
| 不可变标签 | prototype/YYYY/月.日-序号，解析得到完整提交号 |
| 更新内容 | 具体变更；仅文档也如实标明 |
| 文档同步 | 本次相关产品、设计及交付文件 |
| 验证结果 | 实际执行的检查及结果，不把未执行项写成通过 |
| 用户验收 | 已验收或待验收，明确范围和日期 |
| 站点状态 | 未部署或单独记录的部署事实，不能用 Git 推送替代 |

台账随交付提交一起保存，因此本次记录通过标签引用该提交，不手填尚未生成的自身 SHA。交付后由远端标签确定最终完整提交号，群通知使用真实短提交号。远端标签未就绪时属于交付未完成；不能仅凭台账条目认定已成功推送。

后续验收或站点部署改变交付状态时，在操作记录／通知中引用同一基线；需要修改台账文件时随下一次正常交付更新，不为补写一个状态假装重新发布业务功能。不得移动原标签。
